# 02 · 可爱且不散架的聊天陪伴人偶

状态：待美术与动效样例评审。**推荐精修 Q 版原画 + Live2D 小幅转头；不将当前 SVG 修几个坐标后直接宣布完成。**

## 1. 当前问题的真实来源

基线为 `046564cea422d7edeee686f5c3b404090d15e6f6` 的 `AppShell.tsx` 和 `foundation.scss`。

当前角色是代码绘制的 SVG，不是参考图角色的专业分层绑定模型。它把头部做平移和 Z 轴旋转，再单独平移两个虹膜及高光。这里要准确区分：**虹膜节点确实在头部组里，不是完全没有父子关系；但没有眼眶裁剪，头部也没有左右转脸的透视/网格变形。**

眼白椭圆半径为 `(7, 6)`，虹膜半径为 `(4.2, 4.8)`，虹膜还会沿 Y 方向移动最多 1.7 CSS px。没有遮罩时，极限方向存在越过眼白边缘的条件。修复必须同时考虑眼眶形状、SVG 坐标到屏幕的缩放、眼睑遮挡和可移动范围，不能只检查虹膜中心是否还在眼白中心附近。

跟随输入是 `(鼠标位置 - 人偶中心) / 人偶自身半宽或半高` 再限制到 `[-1, 1]`。人偶只有 96 × 126 CSS px，因此鼠标在正常工作区移动时非常容易一直处于极限值。页面内的“头随鼠标转”实际上大量时间只是维持一个最大歪头姿势。

它还无条件挂在 `AppShell` 的所有页面里；`left:14px/bottom:14px` 是相对主内容容器，不是经过避让设计的应用左下角。`current-companion-repro.html` 可查看原有几何和三个方向的隔离复现；那不是拟交付的新角色。

## 2. 选型：画得好看与动得正确分开解决

| 方案 | 对本项目的判断 |
| --- | --- |
| 单张 PNG + 整体倾斜 | 可用作加载失败/减少动态效果时的备用图；无法作为自然转脸、独立眼神的完整交付 |
| 精修分层 2D + Live2D Cubism Web | **首选。** 保留参考图的插画气质，通过已制作好的头部变形、眼球参数、遮罩与眨眼实现小幅自然互动 |
| 真实 3D：绑定好的角色模型 + Three.js 等渲染 | 可行，但需要角色建模、材质、眼球/头骨绑定、光照和模型优化。更适合明确想要立体手办材质、明显侧面或较大角度转动的方向；本次没有必要先引入整套 3D 美术制作 |

这是一项针对当前风格和交互范围的选型，不是说 Live2D 一定比所有 3D 项目更轻、更便宜，或换个库就会自动变可爱。Live2D 需要实际制作并验证模型；普通 PNG、几张生成的分离瞳孔图或一个空的 `.model3.json` 都不能替代它。

ChatGPT 图片生成适合先做角色原画、配色和多角度设计参考。**一张“3D 风格图片”与可被程序控制的带绑定模型是不同产物。** 即使原画由 AI 生成，拆层、补全遮挡区域、眼眶遮罩、变形与眨眼仍要处理；不能承诺一张图一键变成高质量可转动人偶。

## 3. 固定一个可爱的角色方向

优先保持首页与详情为同一个“记录员”角色，而不是首页是精修少女、详情突然换成另一种画风的几何小人。

设计建议：约 2.3–2.6 头身的大头短身 Q 版，圆润脸颊和自然小嘴，柔和棕色短发，琥珀色虹膜，雾蓝发饰/开衫，奶白内搭、灰粉蝴蝶结和小笔记本。使用轻柔棕灰线条，避免当前大圆眼白配高饱和红色眼珠、厚黑轮廓与硬直四肢。可爱主要由轮廓、脸部比例、眼神和姿势决定，不由摆动幅度决定。

桌面显示高度先按 160–180 CSS px 试排，小窗用约 140 px 或静态缩略状态。**必须在最终显示尺寸评审，不只看大尺寸原画。** 本轮只选择一套一致的角色资产；更换为小动物吉祥物也应先交独立静态稿评审，不在接入时自行换风格。

### 美术资产交付要求

先提交透明背景正面中立姿态、闭眼姿态以及左右小角度外观设计；这些用于审美和绑定核对，多角度设计图不是运行时逐帧切换贴片。原画没有通过“够不够可爱”的评审前，不进行正式接入。

需要可编辑的分层源文件，至少区分身体、颈部、后发、脸、左右眼白、左右虹膜/瞳孔/高光、上下眼睑/睫毛、眉、嘴、腮红、前发、发饰；被头发和眼睛遮挡的底图必须补全，避免旋转露洞。左右眼高光随各自虹膜移动，眼睑和眼眶随脸部变形。

Live2D 交付应包含实际可加载的 `.model3.json`、`.moc3`、纹理，以及模型使用的表情/物理/动作文件；另附已批准的静态备用图、参数范围说明和素材/SDK 分发许可记录。不要引用不明来源的角色包，也不要把缺少 Core 或模型资产的运行时代码标成可直接使用。

## 4. 跟随：先眼神、再轻微转头，而不是追着光标乱甩

实现需要明确一个控制器，其他代码不能分别覆盖同一套头部/眼球参数。推荐 `CompanionController` 负责输入、阻尼、显隐与参数合成，渲染适配器只负责把受约束的姿态映射给模型。

坐标以窗口/工作区的交互范围和脸部位置计算，使用足够大的感应范围与柔和的饱和曲线，避免小人偶自身的几十个像素就把输入推满。屏幕坐标 Y 方向、模型坐标 Y 方向及模型默认朝向要显式转换，不允许左右或上下反向。

眼神比头部略快：可先尝试眼球 80–120 ms、头部 160–240 ms 的平滑时间尺度，采用基于实际帧间隔的阻尼，不用每帧固定插值系数绑死刷新率。头部视觉范围先按左右约 10–12 度、上下约 6–8 度、轻微歪头不超过约 3 度试调；**这些是外观目标，不是直接把角度数字写入 `ParamAngleX/Y` 的保证。模型参数单位、有效范围和具体变形必须按资产实测映射。**

左右虹膜分别限制在各自眼眶内，使用眼眶遮罩/模型 clipping；闭眼时由眼睑完整遮挡，不允许“眼睑闭了但瞳孔仍浮在脸上”。虹膜、高光、睫毛和脸属于同一正确的变形层级。极限转头 + 极限眼神 + 眨眼必须组合验证，不能只在正视时验证。

头部绕正确的颈部连接区域变化，不靠把整颗头平移出身体制造转向。身体可以有更小的跟随；头发和蝴蝶结可有轻微滞后，不做持续夸张漂浮。指针离开窗口或窗口失焦后，先取消未执行的跟随帧，再回到中立状态，避免刚复位又被旧回调拉走。

## 5. 出场位置和页面生命周期

首页：只渲染右上大幅插画，不安装全局人偶 pointer listener，不加载动态模型。

真实聊天详情：右上插画退出后，小人偶从应用左下角轻轻探出，入场可先试 320–420 ms；不是把大图沿对角线飞过消息列表再缩小。进入其他页面隐藏/卸载动态人偶。首页只是选择群组时，不出场。

左下角必须是布局预留的安全区域：在展开导航底部为人偶建立约 150 × 190 px 的停靠位，将账号/连接状态与引导入口安排在它上方；人偶不直接覆盖这些入口。紧凑布局没有空间时改为小型入口或隐藏，由用户展开；不能任由绝对定位覆盖群列表最后几项、最后一条消息或输入框。

装饰画布默认 `pointer-events:none`；隐藏/显示按钮单独可交互、可键盘操作，并保存用户选择。拖拽分栏、选择文本、点击消息不能被画布拦截。

动态资源仅在明确进入聊天详情且允许动画时懒加载。取消加载、切群、离开页面、React StrictMode 重挂载都必须安全；销毁模型、纹理、事件监听和动画帧。页面不可见时暂停，重新可见后重置时间基准，防止积累的大帧间隔导致跳动。仅 CSS `display:none` 不等于释放监听和渲染循环。

`prefers-reduced-motion`、触摸/无精确指针、WebGL 不可用或模型加载失败时使用已批准的静态备用图；运行中修改减少动态效果设置也要生效。备用图不构成“动态人偶已经验收通过”。

## 6. 建议文件边界

建议新增 `features/companion/`：`CompanionHost.tsx` 管路由显隐和停靠，`CompanionController` 管输入与姿态，Live2D 适配器管模型加载/绘制/销毁，样式只负责布局；静态图与动态模型使用一个资产清单管理。名字可按项目规范调整。

`AppShell.tsx` 删除当前内联 `CompanionDoll`，不要继续把几十条 SVG 人物路径和全局监听塞在公共布局中。是否显示由显式聊天详情状态驱动，而不是组件自行猜 DOM 或通过当前有没有消息来判断。

优先不更改数据库、话题检索、AI 调用和微信协议。本功能也不需要摄像头、面部追踪、上传鼠标轨迹或额外的 AI 网络调用。

## 7. 合并门槛

必须提供静态原画 + 独立动作样例 + 集成页面证据，三者缺一不算完成。

动作样例至少覆盖中间、上、下、左、右与四个角共九个方向，指针快速画圈/横穿、停止后的收敛、极限方向眨眼、窗口缩放、不同显示缩放、失焦复位。观察目标：没有瞳孔出眶、重复眼睛、透底、脖颈裂缝、发片露缝或明显抖动。

集成检查覆盖首页 → 详情 → 设置 → 返回；人偶不挡输入/连接状态/最后一条消息；可关闭；减少动态效果和触摸模式不启动跟随；组件卸载后不残留监听与 rAF；隐藏窗口停止绘制。性能记录要写测试硬件、窗口尺寸、模型大小、首载耗时、帧时间和空闲占用，不以“理论上 60fps”代替测量。

**明确拒收**：只给新的人物文字描述；把完整角色图片做 `rotateY` 当作真实转脸；只缩小瞳孔移动但不修遮罩；随便切几张尺寸/眼位不同的生成图；再次交付一个未经静态评审的粗略 SVG 小人；用漂亮的概念图冒充实际 Electron 运行效果。

- [Live2D Parameter Operation](https://docs.live2d.com/en/cubism-sdk-manual/parameters/)：头部、眼球等参数分别更新，示例展示拖动、眨眼、呼吸等参数合成。它证明控制机制存在，不证明任何输入原画会自动变成合格模型。
- [Live2D About Models (Web)](https://docs.live2d.com/en/cubism-sdk-manual/model-web/) 与 [Mask preprocessing (Web)](https://docs.live2d.com/en/cubism-sdk-manual/ow-sdk-mask-premake-web/)：模型加载与遮罩机制。
- [Three.js Object3D](https://threejs.org/docs/pages/Object3D.html)：真实 3D 场景中的对象层级与变换；仍需配套美术模型。
- [OpenAI Images in ChatGPT](https://help.openai.com/en/articles/11084440-chatgpt-images-faq)：图像创建和编辑能力。图像产物不能直接等同于已绑定、能驱动的 3D/Live2D 模型。

本文件的角色比例、显示尺寸、缓动时间和转头幅度均为项目建议初值，需要实际素材和目标设备验证，尚不是达成的产品效果。
