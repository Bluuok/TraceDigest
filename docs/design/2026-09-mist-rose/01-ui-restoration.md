# 01 · 暖白、雾蓝、灰粉的界面还原

状态：待实施。所有路径以 `046564cea422d7edeee686f5c3b404090d15e6f6` 为审查基线。

## 1. 为什么现在看起来灰暗

这不是一句“提高亮度”能解决的问题。

| 已核对的实现 | 与参考图的差距 | 实施要求 |
| --- | --- | --- |
| `styles/tailwind.css` 的浅色主色仍为 `166 52% 33%`，表面多为冷灰蓝；`styles/_tokens.scss` 把这些值映射给 `--wxex-*` | 原产品的灰绿主题，不是参考图的灰粉、雾蓝主题 | 从 `--tm-*` 源头统一色板，检查所有 `--wxex-*` 消费者，而不是只改最外层背景 |
| `App.tsx` 初始主题为 `system`，随后读取持久化设置；`theme.scss` 和 `tailwind.css` 都处理系统暗色 | 操作系统为暗色时还会切为真正的深色；不能仅凭用户的描述断言其当前系统设置 | 参考图验收显式使用 `light`；保留用户主动选择的 `dark/system`，不要悄悄覆写其设置 |
| `foundation.scss` 的旧变量仍包含 `#f5f5f5`、`#e7e7e7`、`#95ec69` 等 | 局部聊天区域可能保留旧产品视觉，单改新 token 不等于全页面统一 | 检索实际引用并映射语义 token；不能盲删旧变量或把错误、成功色也改成粉色 |
| `_tokens.scss` 导航宽度为 76 px，`AppShell` 的品牌只有图标 | 参考图是有品牌文字、横排图标与菜单文字的展开式导航 | 首页建立展开式导航，窄窗才折叠，避免拿 76 px 图标栏假装完成还原 |
| `navigation.ts` 只有 `ask-ai/report/agent-hub/export/settings`；`AskAIWorkspace.tsx` 把 `TopicPanel` 插进右侧 AI 对话栏 | 参考图中的主内容“话题整理”没有成为独立首页 | 明确增加话题概览与聊天详情两个视图，不只是改菜单名 |

已检查的 `src/renderer/src/assets` 目录只有品牌图标、Electron 图标和波纹 SVG，没有参考图里的精修人物资产。不能把“挂上一个人偶组件”当成已完成插画落地；也不据此断言其他未检查目录绝无素材。

## 2. 固定视觉方向

参考图：用户提供的 1073 × 668 TraceDigest「C · 雾蓝灰粉」。还原的是整体比例、明暗层级、配色和插画气质，不是把截图作为一张背景铺在应用下面。

整体以暖白为底，白色内容卡片、低饱和雾蓝证据区、少量灰粉按钮和选中状态。正文为深蓝灰，不能为了“柔和”把文字也一起降低透明度。花瓣仅在空白边缘出现，主内容不加整页灰蒙蒙滤镜、磨砂遮罩或大面积暗渐变。

下面是**建议初始值，不是声称从原图精确采样得到的唯一标准**：

| 用途 | 建议值 |
| --- | --- |
| 应用底色 / 内容卡片 | `#FBF9F7` / `#FFFFFF` |
| 雾蓝信息区 | `#EDF3F7` |
| 粉色选中底 | `#F4E7EC` |
| 主要按钮 / 白色按钮文字 | `#A85F77` / `#FFFFFF` |
| 主文字 / 次文字 | `#344657` / `#68788A` |
| 粉色文字 / 分隔线 | `#89556A` / `#E4E9EF` |

用相对亮度公式计算，白字 / 主要按钮约 4.60:1，主文字 / 应用底色约 9.26:1，次文字 / 白卡约 4.52:1，粉字 / 粉色选中底约 4.90:1。结果见 `validation.json`。这些只是指定实色组合的计算；最终透明叠层、hover、disabled、placeholder、字号与实际背景都要重新检查，不能当成全应用可访问性认证。

主题策略：将现有 `light` 视觉方案改为本轮 C 风格，避免未经设计就新增不兼容的主题枚举。首次安装的默认主题、旧设置的保留与初始渲染的主题同步要一起检查。仅把 `AppShell` 参数默认值从 `system` 改成 `light` 不够，实际调用方和持久化配置仍可能传入 `system`。

## 3. 首页与聊天详情必须分开

### 话题首页

建议新增明确的 `topics` 页面标识，作为此次设计的主入口。现有 `ask-ai` 保留为消息浏览与 AI 对话工作区，原有日报、Clawbot、导出和设置入口继续可达。参考图中的兴趣标签、数据洞察没有对应完整功能前，不放置看似可点击但没有行为的假入口。

桌面参考尺寸下，主导航约 148–156 px，群组栏约 165–190 px，余下空间是话题主内容。宽度是起始设计值，必须通过真实内容与窗口尺寸验证，不是无条件固定死的像素拼图。

主内容顺序应接近参考图：

- 上方：文件夹图标、话题整理标题、简短说明；右上角是精修的大幅角色插画和少量手写感装饰。
- 下方：关键词、日期范围、生成话题包操作；常用条件直接显示，别名、排除项和成员等收进高级筛选，但不删除功能。
- 结果：话题摘要卡、关键证据列表，以及当前选中的原始消息详情；底部是有真实数据支持的相关话题。

插画应有专用装饰层和留白区域；不要用高 z-index 压住生成按钮、筛选项或证据详情。插画本身不拦截指针事件；尺寸不足时先缩小或隐藏装饰，而不是挤掉正文。

### 聊天详情

用户点击“进入聊天”或“查看原文”后，再显示消息浏览与 AI 对话工作区。右上大插画消失，左下角出现 Q 版陪伴人偶。详情页继承配色，但减少装饰，优先保证聊天记录和输入区域。

视图状态必须是显式的，不能仅用 `selectedContact != null` 认定用户已经进入详情：当前 `AskAIWorkspace` 会自动选择第一个群，这不是用户执行了“进入详情”。首页选群也不应触发人偶出场。

返回首页应保留群组、关键词、时间范围、结果和所选证据；切群时重置不属于新群的选择。当前 `TopicPanel.locateEvidence` 只是对本面板的证据节点 `scrollIntoView`，不等于打开并定位真实聊天原文。实施时应使用可核对的群组与消息身份定位；尚未加载的消息需要明确加载/未找到状态，不要用一个假跳转按钮掩盖缺失能力。

## 4. 只重组 UI，不丢掉数据约束

将 `TopicPanel` 的查询、生成、证据选择等逻辑提取为可复用模型或 hook，再做首页呈现。不要为还原图片，另写一套与真实后端脱离的 mock 业务。

必须保留 `groupId`、主题、别名、排除项、成员、时间边界与时区；候选证据、原始消息来源、生成失败和无结果状态都需要真实展示。人工调整候选证据后，当前实现会使原有总结失效；这个行为必须继续保留，不能为了界面干净隐藏警告或继续展示旧结论为有效。

标签数量、相关话题、证据数量不能照抄参考图中的示例数字。接口没有返回分类/关联结果时，应省略对应展示或明确空状态，不能从几条文字凭空拼出可信事实。导出、订阅保存/启停与投递相关的业务保持原语义。

## 6. 合并前验收

同一批真实或明确标注的测试数据，提交 1073 × 668 参考比例、1280 × 800、1440 × 900 的首页/详情截图，并检查窄窗和 Windows 显示缩放。参考图对照必须使用浅色模式，另测显式深色和跟随系统，不能把主题状态不一致的截图作比较。

需要检查：首页没有小人偶，详情没有大插画；搜索、日期、生成、选证据、查看原文、返回、导出和订阅仍可操作；人物不遮住控件；长群名与长消息不溢出；所有数字来自当前数据；键盘焦点清楚；空、错、加载态不是一大片灰色占位。

审美验收看同尺寸的真实页面，而不是只看单独的配色表、局部 CSS 或 AI 生成的整页概念图。
